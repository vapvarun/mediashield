# MediaShield 1.2.0 — In-Video Ads + No-Skip: Code Flow

Goal: YouTube/Prime-style in-video ads (pre-roll + 2-3 mid-rolls + optional
post-roll) and true forward-seek prevention, on Bunny-hosted lesson videos.
**Decoupled design:** MediaShield owns the player *engine*; WB Ad Manager owns
the ad *creatives* (new "video" ad type). MediaShield reads them via a bridge,
so it never hard-depends on the ad plugin.

## End-to-end flow

```
WB Ad Manager (Pro)                      MediaShield (Free)
─────────────────────                    ──────────────────
Video_Ad type  ──creatives──►  AdManagerBridge ──filter──►  Player\Renderer
(video_url,                    (mediashield_video_         emits data-ad-breaks
 click_url,                     ad_breaks)                 + enqueues ad-breaks.js
 skip_after)                                                      │
                                                                  ▼
                                            ad-breaks.js engine (on mediashield:player-ready)
                                              pre  → hold main, play ad, resume
                                              mid  → at timecode: pause, play ad, resume
                                              post → on ended: play ad
                                              (countdown + optional skip)
```

Playback control requires a **native `<video>`** (Bunny via signed HLS), not the
opaque iframe embed — see "Native HLS" below.

## Remaining wiring (precise steps)

1. **Register the bridge** — in `MediaShield\Core\Plugin` boot:
   `( new \MediaShield\Integrations\AdManagerBridge() )->register();`
   (add the `require`/autoload entry for `includes/Integrations/`).

2. **Renderer emits breaks + enqueues engine** — in `Player\Renderer`, where the
   `.ms-protected-player` container is built:
   ```php
   $breaks = apply_filters( 'mediashield_video_ad_breaks', array(), $video_id, (int) $duration );
   if ( $breaks ) {
       // add to the container: data-ad-breaks="<?php echo esc_attr( wp_json_encode( $breaks ) ); ?>"
       wp_enqueue_script( 'mediashield-ad-breaks' ); // register in Core\Assets
   }
   ```
   Register `mediashield-ad-breaks` (assets/js/ad-breaks.js) in `Core\Assets`,
   dependency `mediashield-player-wrapper`. Add `.ms-ad-overlay*` styles to
   `assets/css/player.css`.

3. **Native HLS playback** (unblocks both ads + no-skip) — in `player-wrapper.js`
   `createAdapter()` `case 'bunny'`: use `NativeAdapter` when `sourceUrl` is an
   HLS/DASH playlist (`.m3u8`/`.mpd`), else the iframe. Trigger Shaka load
   (`mediashield_needs_shaka` filter) for those. `_ms_source_url` must be the
   **signed** HLS URL — `BunnyStream::get_streaming_url()` already signs when
   `cdn_token_key` is present.

## The one external dependency

Bunny's pull zone has **Token Authentication ON** (direct `.m3u8` → 403). So the
native path needs the **CDN Token Authentication Key** stored on the connection
(`extra_config.cdn_token_key`). The connect form already collects it
(`Platforms.js` → Pull Zone + CDN Token Key). Once set:
`get_streaming_url()` → signed HLS → native `<video>` → engine + no-skip live.

Until then the iframe embed keeps playing for viewing; ad breaks + no-skip
stay dormant (the engine bails out cleanly on an opaque embed).

## Data shapes

```js
// data-ad-breaks (per player)
[ { id, type:'pre'|'mid'|'post', at:<sec>, skipAfter:<int|null>, html:'<video…>' } ]
```
```php
// _wbam_ad_data for a video ad
[ 'type'=>'video', 'video_url'=>'', 'click_url'=>'', 'skip_after'=>0 ]
```
