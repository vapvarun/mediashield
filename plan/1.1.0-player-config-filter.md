## What this plan scopes

The FREE-side contributions that mediashield-pro 1.1.0 (Ads on Videos) requires. Everything substantial — the timeline scrubber, the player runtime, the skip button, the cross-analytics — lives in PRO. This plan is just the two FREE-side hooks PRO needs to do its work.

> **⚠️ ARCHITECTURAL PRINCIPLE:** mediashield FREE owns the **video player + protection layer**. Ad management lives in mediashield-pro and wb-ad-manager-pro, which integrate via this filter. FREE itself stays focused on protection + playback; ads are an extension, not a core feature.

## IN scope (mediashield FREE 1.1.0)

### 1. New filter: `mediashield_player_config`

A filter that lets PRO inject per-video runtime configuration into the player. The filter exists already implicitly (in the form of various ad-hoc filters), but this consolidates it into one canonical extension point.

```php
/**
 * Filter the player runtime config emitted into the page for a video.
 *
 * @param array $config   Player config — keys: source_url, dimensions, watermark, session_token, ...
 * @param int   $video_id The mediashield_video post ID.
 */
$config = apply_filters( 'mediashield_player_config', $config, $video_id );
```

PRO hooks this to add `$config['ads']` containing the video's ad-slot configuration. FREE doesn't care what PRO puts there; FREE just emits the config to the page where PRO's runtime JS reads it.

**Implementation:** find the existing config-emission point (likely in `Block\VideoBlock::render` or `Player\PlayerWrapper::render_player`) and wrap the final config array with the filter call. ~5 lines of code.

### 2. Promote player JS events to public stable contract

mediashield's player wrapper already emits these JS events:

- `mediashield:player_ready` — fires when player is initialized and ready
- `mediashield:play` — playback started
- `mediashield:pause` — playback paused
- `mediashield:timeupdate` — fires periodically during playback (~250ms resolution)
- `mediashield:ended` — playback completed
- `mediashield:seeking` — user is scrubbing

**What changes:** these events become part of the public foundation contract. They're guaranteed stable for the lifetime of the major version per the foundation principles in `docs/architecture/PLUGIN_ARCHITECTURE.md`. Documented in the existing `docs/free/hooks-filters.md` under a new "JS Events" section.

**Implementation:** purely documentation. The events already fire. No code change needed.

### 3. Document `_ms_ads_config` post meta convention

`_ms_ads_config` is a per-video post meta key that PRO will use to store ad-slot configurations. FREE doesn't read or write it — but it documents the convention so 3rd-party plugins know not to clobber it.

**Implementation:** add to `docs/free/hooks-filters.md` under "Reserved post meta keys" → "_ms_ads_config (reserved for mediashield-pro Ads on Videos feature)".
