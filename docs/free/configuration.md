# MediaShield -- Configuration Guide

All settings are managed from the **MediaShield > Settings** admin page, a React single-page application with auto-save. The canonical source of truth is `includes/Core/Settings::schema()` -- the table below is generated by hand from that file and audited before each release.

Every option name in this guide is validated server-side (`Settings::sanitize()`); invalid values are silently rejected and the previously stored value is kept. Numeric ranges are clamped rather than rejected so the admin UI feels forgiving.

---

## General Settings

| Setting | Option Key | Default | Description |
|---------|-----------|---------|-------------|
| Enable Protection | `ms_enabled` | `true` | Master toggle for all video protection features |
| Default Protection Level | `ms_default_protection` | `standard` | Baseline protection: `none`, `basic`, `standard`, `strict`. Used when a video has no per-video override. Other values are rejected. |
| Require Login | `ms_require_login` | `true` | Force login before any video playback |
| Show Badge | `ms_show_badge` | `true` | Display "Protected by MediaShield" badge on player |

### Protection Levels

- **None** -- No protection applied, videos play as normal embeds.
- **Basic** -- Right-click disabled, source URL hidden.
- **Standard** -- Basic + dynamic watermark overlay + devtools detection.
- **Strict** -- Standard + keyboard shortcut blocking + fullscreen watermark.

## Watermark Settings

| Setting | Option Key | Default | Validation |
|---------|-----------|---------|------------|
| Opacity | `ms_watermark_opacity` | `0.5` | Clamped to `[0, 1]` |
| Color | `ms_watermark_color` | `#ffffff` | Hex regex `/^#([A-Fa-f0-9]{3}|[A-Fa-f0-9]{6})$/`, normalised to lowercase |
| Swap Interval | `ms_watermark_swap_interval` | `30` | Minimum `1` second |

The free watermark displays the logged-in user's display name and IP address. Pro adds 7 configurable fields (username, email, IP, user ID, timestamp, site name, custom text).

## Access Control

| Setting | Option Key | Default | Validation |
|---------|-----------|---------|------------|
| Max Concurrent Streams | `ms_max_concurrent_streams` | `2` | Minimum `1` |
| Allowed Domains | `ms_allowed_domains` | `''` | Comma-separated domain whitelist for embed access. Empty disables the check. |
| Login Overlay Text | `ms_login_overlay_text` | _"Please log in to watch this video"_ | Sanitised via `sanitize_textarea_field` |
| Login Button Text | `ms_login_button_text` | _"Log In"_ | Sanitised via `sanitize_textarea_field` |
| Access Denied Text | `ms_access_denied_text` | _"You do not have access to this video"_ | Sanitised via `sanitize_textarea_field` |

When `ms_allowed_domains` is non-empty, the request's HTTP Referer (raw, not WP's validated form) must match the whitelist or originate from the same host. Empty-Referer requests deny by default; opt back into the legacy permissive behaviour with `add_filter( 'mediashield_allow_empty_referer', '__return_true' )`.

## Upload Settings

| Setting | Option Key | Default | Validation |
|---------|-----------|---------|------------|
| Max Upload Size | `ms_max_upload_size` | `500` | Minimum `1` (MB) |

Self-hosted uploads are stored in `wp-content/uploads/mediashield/` with `.htaccess` protection. A REST API proxy endpoint serves files after access verification.

## Custom URL Patterns

| Setting | Option Key | Default | Description |
|---------|-----------|---------|-------------|
| Custom URL Patterns | `ms_custom_url_patterns` | `''` | Additional URL patterns for the output buffer video detector |

Use this to match custom video embed URLs that MediaShield doesn't detect automatically. One pattern per line. Supports wildcards.

## Player Controls

Global defaults for the player UI surface. Each can be overridden per video via the Video CPT metabox (tri-state: on / off / inherit).

| Setting | Option Key | Default | Description |
|---------|-----------|---------|-------------|
| Speed Control | `ms_player_speed_control` | `true` | Show the playback-rate menu (self-hosted / Bunny only) |
| Sticky Player | `ms_player_sticky` | `false` | Pin the player to a corner when scrolled off-screen during playback |
| Keyboard Shortcuts | `ms_player_keyboard` | `true` | Allow Space/Arrow/M/F shortcuts on the player |
| Resume Playback | `ms_player_resume` | `true` | Resume from the last reached position when re-opening a video |
| End Screen | `ms_player_endscreen` | `false` | Render the end-screen CTA when the video ends |
| End Screen Text | `ms_player_endscreen_text` | `''` | CTA text shown on the end-screen card (global fallback when a video doesn't set its own) |
| End Screen URL | `ms_player_endscreen_url` | `''` | CTA URL. Empty allowed; otherwise must survive `esc_url_raw` (rejects `javascript:` URLs) |

Per-video meta keys mirror these names with the `_` prefix, e.g. `_ms_player_endscreen_text` overrides the global.

## Protection Controls

Server-side toggles consumed by the frontend protection runtime (`assets/js/protection.js` + `Player\Protection`).

| Setting | Option Key | Default | Description |
|---------|-----------|---------|-------------|
| Block Right-Click | `ms_block_right_click` | `true` | Disable the browser context menu over protected players |
| Block Keyboard Shortcuts | `ms_block_keyboard` | `false` | Disable Ctrl/Cmd+S, Ctrl+U, F12 and similar capture shortcuts on player pages |
| Hide Source URL | `ms_hide_source` | `true` | Strip `src=` attributes from rendered video elements (the JS adapter reads them via dataset instead) |
| Detect Devtools | `ms_detect_devtools` | `true` | Detect open browser devtools and dispatch a beacon to `/protection/devtools-event` |
| Pause on Devtools | `ms_pause_on_devtools` | `false` | When devtools open, pause playback in addition to the overlay |
| Devtools Overlay Title | `ms_devtools_title` | _"Developer Tools Detected"_ | Heading shown on the devtools-overlay |
| Devtools Overlay Message | `ms_devtools_message` | _"Please close developer tools to continue watching this video."_ | Body copy below the heading |

## Per-Video Settings

Each video (CPT `mediashield_video`) has its own meta settings that override global defaults:

| Meta Key | Description |
|----------|-------------|
| `_ms_platform` | Hosting platform (`self`, `youtube`, `vimeo`, `bunny`, `wistia`) |
| `_ms_platform_video_id` | External platform video ID |
| `_ms_source_url` | Direct video URL |
| `_ms_protection_level` | Per-video protection level override. Empty string means "inherit `ms_default_protection`". |
| `_ms_access_role` | Required WordPress role (empty = all roles) |
| `_ms_duration` | Video duration in seconds |

### Playback options

| Meta Key | Type | Notes |
|---|---|---|
| `_ms_autoplay` | `'1'` / `'0'` | Tri-state via metabox checkbox |
| `_ms_loop` | `'1'` / `'0'` | YouTube uses the `playlist=<id>` workaround so loop actually loops |
| `_ms_muted` | `'1'` / `'0'` | — |
| `_ms_show_controls` | `'1'` / `'0'` | Self-hosted only |

### Player feature overrides (tri-state)

| Meta Key | Values |
|---|---|
| `_ms_player_speed` | `''` (inherit) / `'on'` / `'off'` |
| `_ms_player_keyboard` | `''` (inherit) / `'on'` / `'off'` |
| `_ms_player_resume` | `''` (inherit) / `'on'` / `'off'` |
| `_ms_player_sticky` | `''` (inherit) / `'on'` / `'off'` |
| `_ms_player_endscreen` | `''` (inherit) / `'on'` / `'off'` |
| `_ms_player_endscreen_text` | string (empty = inherit `ms_player_endscreen_text`) |
| `_ms_player_endscreen_url` | URL (empty = inherit `ms_player_endscreen_url`) |

### Milestone Tags

Each video can have tags assigned per milestone percentage (25%, 50%, 75%, 100%). When a user reaches that milestone, the tag is promoted into the unified `ms_tags` dictionary (via `TagManager::ensure()`), linked to the source video in `ms_video_tags`, and the canonical `tag_id` is stored alongside the display string in the user's `_ms_video_tags` meta. Configure these in the video editor sidebar.

## Settings REST API

Settings are managed via REST endpoints:

```
GET  /wp-json/mediashield/v1/settings   -- Retrieve all settings (typed)
PUT  /wp-json/mediashield/v1/settings   -- Update settings (partial updates supported)
```

Both endpoints require `manage_options` capability. Each PUT key is run through `Settings::sanitize()`:

1. Unknown keys are silently ignored (so Pro can add its own keys via the `mediashield_settings_update` filter without colliding with Free).
2. Known keys are type-cast (boolean / integer / float / string).
3. Validated per the table above. A validator returning `null` (e.g. junk hex colour, out-of-enum protection level) causes the update to be skipped -- the previously stored value sticks.

Pro extends both paths via the `mediashield_settings_response` (GET) and `mediashield_settings_update` (PUT) filters.
