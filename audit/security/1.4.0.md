# MediaShield 1.4.0 security review

Scope: Free and Pro, `v1.3.0..1.4.0`. Mechanical sweep, two route spot-checks, a reviewed diff (read-only, no runtime calls) and the bugs QA filed during the cycle.

## Sweep (G1)
`security-sweep.sh` finds no CRITICAL pattern in either repo. Pro counts are identical to v1.3.0. Free has one more `nonce-only-auth` hit and two more routes than v1.3.0:
- `GET /stream/{id}/url`: mints a fresh signed address after `AccessControl::can_watch()`. Changes nothing.
- `GET /playlists/{id}/player/{video}`: returns the rendered player for an item of a published playlist. See finding 1.

## Fixed in 1.4.0
| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | High | A CDN-signed stream address (Bunny direct play, Pro) was printed in player HTML for viewers who may not watch, and the new playlist player route served that HTML to anyone. Direct play is off by default. | `Renderer` blanks any non-self-hosted stream URL unless `can_watch()` passes. Self-hosted addresses stay routed through `/stream`, which checks on every request. |
| 2 | Medium | The page printed the visitor's name and IP in the watermark config, so a page cache could show them to the next visitor. | Removed from the page config. `/session/start` still supplies both. |
| 3 | Medium | A flood of made-up heartbeat tokens each got its own rate bucket and wrote an options row. | A token we did not sign shares one bucket per caller. |
| 4 | Medium | The session token timestamp was cast before it was signed, so one token had endless spellings. | Signed over the raw fields. |
| 5 | Low | The embed token had the same flaw. | One accepted spelling. |
| 6 | Low | The playlist player route ignored a playlist password. | Returns 404 while the password is required. |

Each fix has a unit test that fails on the old code.

## Scanner-visible but safe
- `sql-direct-interpolated`: table names only, values go through `prepare()`.
- Platform embed IDs (YouTube, Vimeo) are visible to anonymous visitors. They are in the embed the viewer loads; the gate is the session and the login overlay.
- `holder.innerHTML = data.html` in the playlist view script: the HTML comes from the server renderer, which escapes.
- `HealthCheck::ajax_test` has a nonce and a capability check. `get_credentials()` in Pro is called server-side only and no key reaches the browser.
- Path traversal in `resolve_file`: `realpath` must sit under the uploads root and only video extensions are served.
