# MediaShield 1.4.4 security review

Scope: Free and Pro, `v1.4.3..1.4.4`. The record covers:
- the mechanical sweep (G1);
- the authorisation matrix, now a unit test in both repos (G2);
- the reviewed diff of every permission, file and request-handling change (G3);
- an independent QA verification of the release cards in Docker labs, including a real 1.4.3 to 1.4.4 update with Free and Pro.

Release heads: Free `948818e`, Pro `a729d17`.

## Authorisation matrix (G2)
New in 1.4.4, owed since 1.4.3. `audit/route-authority.json` and `tests/unit/RouteAuthorityTest.php` exist in both repos. The manifest was seeded from the live registry (`rest_get_server()->get_routes()`), not from source.

- Free, `mediashield/v1`, 36 routes: admin 20, owner 6, guarded 8, member 1, public 1.
- Pro, `mediashield-pro/v1`, 38 routes: admin 37, public 1. No route behind a feature toggle in either.

The test fails when:
- a live route is undeclared, or a declared route is gone;
- the permission callback that runs is not the declared one;
- a member, owner or admin route lets a signed-out caller through;
- a probed route answers a signed-out request for a private video in a published playlist;
- the registry comes back empty or nothing is probed (tripwire).

Each check was mutation-proven red, then reverted to green.

Public routes, reasons from observed signed-out dispatches:
- Free `POST /videos/{id}/unavailable` (`code=removed`): a published video answers 200 `{"recorded":false}` and stores nothing; a private or unknown id answers 404.
- Pro `POST /bunny/webhook`: no token and a wrong token answer 403 `invalid_signature`; only the site's token gets past.

## Reviewed diff (G3)
- **Tag routes** (`REST/TagController.php`): as above. Only the admin Tags and Videos screens call them. The edit-video Tags row saves through `save_meta_box()` (nonce, autosave and `edit_post` checks). Member milestone tags are user meta, not these routes.
- **Library REST routes** (`REST/LibraryPostsController.php`): `/wp/v2/mediashield-videos` and `-playlists` need `edit_posts` to read. A visitor no longer lists titles and playback settings.
- **Playlists** (`REST/PlaylistController.php`, `CPT/PlaylistPostType.php`): changes need `edit_post` on the playlist. `source_url` shows only to people who can edit that video. Item counts use prepared IN lists.
- **Video summary and list** (`REST/VideoSummaryController.php`, `VideoListController.php`): both need `edit_posts`. A single card also needs `read_post`. `edit_url` shows only with `edit_post`.
- **Video creation** (`CPT/VideoCreator.php`): needs the type's `create_posts`, `edit_post` on a Media Library attachment, and `publish_posts` to publish (otherwise pending).
- **Meta box save** (`CPT/VideoPostType.php`): the new `_ms_duration` and `_ms_source_held` reads sit after the nonce, autosave and capability checks.
- **Learnomy lesson editing** (`Integrations/Learnomy.php`): the editor-only data needs `learnomy_manage_own_courses` or `manage_options`.
- **Watched spans and stream limit** (`Access/WatchedSpans.php`, `SessionManager.php`): the per-member lock goes through `UploadManager::acquire_lock()`. The stream-limit count runs in a transaction with prepared statements. No new route.
- **Source reports** (`REST/SourceReportController.php`): the one new public route, reviewed under G2.
- **Pro PDF reports** (`Export/PdfExporter.php`, `REST/ExportController.php`): the email link (`admin_post_mediashield_pdf_report`) needs `manage_options` and redirects to the authenticated REST download. Signed-out users are sent to log in. Reports sit in Free's protected folder (deny-all `.htaccess` plus `index.php`) and are pruned after a day. Migrator v8 removes 1.4.3's directly linked reports.
- **Pro CSV export** (`Export/CsvExporter.php`): a cell that starts like a formula is written as text.
