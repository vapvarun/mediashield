# MediaShield 1.4.3 security review

Scope: Free and Pro, `v1.4.2..1.4.3`. The record covers:
- the mechanical sweep (G1);
- the reviewed diff of every permission, file and request-handling change (G3);
- an independent QA verification of every card in Docker labs (WordPress 7.1, Reign 8.1.1, Learnomy 2.3.1 alongside), including a real 1.4.2 to 1.4.3 update with Free and Pro.

Every fixed finding was reproduced on the earlier code before it was verified fixed.

## Sweep (G1)
`security-sweep.sh --baseline v1.4.2` finds no CRITICAL pattern in either repo, and no check gained a hit.

| Repo | Check | v1.4.2 | 1.4.3 | Note |
|---|---|---|---|---|
| Free | `sql-direct-interpolated` | 11 | 10 | The scale CLI and the archive count now use `$wpdb->prepare()` with `%i`. |
| Free | `nonce-only-auth` | 2 | 2 | - |
| Free | `no-abspath-guard` | 6 | 6 | - |
| Pro | `sql-direct-interpolated` | 20 | 10 | The scale CLI seed, teardown and benchmark queries now use `$wpdb->prepare()`. |
| Pro | `no-abspath-guard` | 5 | 5 | - |

Every remaining multi-line query in both repos was read: each goes through `prepare()` or is built only from table names, fixed SQL or values that were prepared on their own. No request data reaches SQL unprepared.

The sweep and the review below were re-run on the release head (Free `d318a5c` plus the fix below, Pro `189655f`), after the last QA cards landed. `gate-check.sh`: every row passes except P2 (admin bundle size), P9 (live platform API calls in the request) and E1 (no `bin/build-release.sh`; the zip is built by `grunt dist`). The owner declined those three for 1.4.3 on 2026-11-20; they are owed in 1.4.4. Plugin Check on the installed zips: Pro 0 errors; Free's 4 rows are all in vendored code (`libs/package-signatures` text domain, the EDD SDK updater and its template).

## Reviewed diff (G3)
- **Learnomy lesson payload** (`Integrations/Learnomy.php`): `AccessControl::can_watch()` now runs for every viewer before a signed `embed_url` is added, not only for guests. A refused member gets no link. Before, the link was minted but failed at the embed page and on every stream request, so no video was exposed.
- **Pro role gate removed** (`Access/RoleAccess.php`): Free's `check_role()` runs first and treats `''` and `any` as unrestricted. A named role still refuses non-members. Pro's copy could only add a wrong refusal (`any` was compared as a role name); its admin bypass never applied, because it returned early on any refusal Free had already made.
- **Self-hosted addresses** (`Player/Protection.php`, `Renderer.php`): a file inside the protected folder, or one the video owns, always plays through the signed `/stream/` URL, whatever Hide Video Source URL says. Strict also forces this. A refused viewer gets no address. One shared helper (`Protection::in_protected_folder()`) decides what is inside the folder. An external URL is never routed to `/stream/`.
- **Allowed Domains** (`AccessControl.php`): a top-level page visit (`Sec-Fetch-Dest: document`) is allowed whatever site linked to it. REST and AJAX requests and the stream are not covered by this, and a frame or embed on another site is still refused. A script can set any header, but it could already omit the Referer, which 1.4.2 allowed, so nothing new opens.
- **Media Library file move and repair** (`Upload/LibraryFiles.php`, Migrator v11): only a file with a Media Library item is moved. The one-off repair moves back only files listed in the video's own `_ms_library_restore` record that had no Media Library item and sat outside `uploads/YYYY/MM`. No path comes from a request. A repaired file is public again, as it was before 1.4.2 (owner decision 2026-11-20).
- **Heartbeat** (`REST/SessionController.php`): `position` has `minimum 0` and an explicit `validate_callback`. The custom `sanitize_callback` had bypassed the schema minimum.
- **Tags field** (`CPT/VideoPostType.php`): saved inside `save_meta_box()` after the nonce, autosave and `current_user_can( 'edit_post' )` checks. A REST or quick-edit save never clears tags.
- **Embed page and PDF styles**: the CSS moved from inline blocks into stylesheet files. The output is the same; nothing user-supplied is printed.
- **Videos list** (`REST/VideoListController.php`, added after the first review): `POST /videos/bulk` needs `edit_posts` and then checks `edit_post` (protection) or `delete_post` (trash, restore) on every id; a video the user may not change is skipped and named, never changed. The per-video `ms_list` REST field (thumbnail, duration, status, used in) is null unless the user can edit that video. The `ms_platform` and `ms_protection` filters are honoured only for users with `edit_posts` (finding 3).
- **Watched time** (`Access/WatchedSpans.php`, `SessionController`): spans arrive on the existing heartbeat and end routes under the session owner's own check, are clamped to the video length and merged server side; no new route.
- **Dashboard and uploads** (`AnalyticsController`, `UploadController`): the new Protection card, first-run steps and chart fill sit behind the existing analytics permission; the size check reads `CONTENT_LENGTH` and the PHP limit only, and the lock stops a second upload from the same user.
- **Times** (`Support/Time.php`): new `mediashield_display_timezone` filter. Display only; it changes no stored or compared value.
