# MediaShield 1.4.2 security review

Scope: Free and Pro, `v1.4.1..1.4.2`. The record covers:
- the mechanical sweep (G1);
- the reviewed diff of every permission, file and outbound-request change (G3);
- an independent QA verification of every security card in Docker labs on WordPress 7.1.4 (PHP 8.1 and 8.5), with old data seeded on v1.4.1 and upgraded.

Every fixed finding was reproduced on the earlier code before it was verified fixed.

## Reviewed diff (G3)
- **Allowed Domains** (`AccessControl.php`): the site's own pages and logged-in members are no longer refused for an empty Referer.
  - A top-level page render is allowed.
  - A frame or embed (`Sec-Fetch-Dest` iframe, frame, embed or object) is still refused.
  - A logged-in member's REST call is allowed unless `Sec-Fetch-Site` is `cross-site`.
  - A guest's REST call is still refused unless `mediashield_allow_empty_referer` opts in.
  - Verified with a real cross-site iframe (another origin), with and without `referrerpolicy="no-referrer"`: refused.
  - Accepted limit: a browser that sends no `Sec-Fetch-*` headers (Safari before 16.4) treats a framed page with no Referer as a direct visit.
- **Media Library file move** (`Upload/LibraryFiles.php`).
  - A file is moved only when its resolved real path is inside the uploads directory and not already in `mediashield/`.
  - The person saving must be able to `edit_post` the attachment, or `edit_others_posts` when the file has no attachment.
  - A restore takes `sanitize_file_name()` of the stored name inside `mediashield/`. No path from the request reaches a rename.
- **Revoke session** (`POST /session/revoke-user`): 401 for a visitor, 403 for a subscriber, admin only.
- **Session end with a position**: authenticated by the HMAC session token, and recorded through the same `heartbeat()` path and checks as a normal heartbeat.
- **Bunny auto-import** (Pro `BunnyWebhookController`).
  - A draft is created only after the token or signature check, only for the connected library, only for an upload dated within 24 hours, and never for a GUID any post ever held, trashed included.
  - A per-GUID lock makes replays and parallel calls create one draft.
  - It's off by default.
- **Bunny Save and test** (Pro `BunnyUrls::verify()`): it follows the playlist from the owner's own pull zone, from the admin button only.
- **Text decoding** (`Support\Text::plain()`): output stays escaped where it is HTML, and is printed as text in React. A title holding `<script>` is shown as text on the Bunny card and the Dashboard notice.

## Fixed in 1.4.2
| # | Severity | Finding | Since | Fix |
|---|---|---|---|---|
| 1 | High | A visitor who had not bought a course could download a self-hosted video that came from the Media Library. | 1.4.1 and earlier | The file moves to the protected folder and plays only through the protected player. |
| 2 | High | Contributors, authors and instructors read every video's file and stream address through the REST API, playlist items included. | 1.4.1 and earlier | Only people who can `edit_post` the video receive them. |
| 3 | Medium | Posters, titles, slugs, GUIDs and the playlist sidebar gave guests the YouTube, Vimeo, Wistia or Bunny ID, and one unauthenticated `GET /wp/v2/media` listed them all. | 1.4.1 and earlier | ID-free poster names, a batched, resumable and idempotent rename of old posters and of placeholder titles and slugs, one safe poster read path, and "Untitled video" for untitled Pro imports. Guest scan after the upgrade: 134 IDs over 1,106 URLs, 0 matches from MediaShield's own data. |
| 4 | Medium | A protected video whose session start failed with a JSON 5xx played without its watermark. | 1.4.1 and earlier | The player stays stopped with a message and Try again. |
| 5 | Low | The stream refresh signed an address for any id the viewer named, and drafts answered differently from unknown ids. | 1.4.1 and earlier | Published videos only; a draft and an unknown id both answer 404 "Video not found." |
| 6 | Low | A self-hosted video's stored file name or a direct protected-folder address was printed on the player page. | 1.4.1 and earlier | Not printed. |
